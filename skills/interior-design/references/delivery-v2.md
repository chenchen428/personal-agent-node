# Interior-design delivery v2

The interior-designer Agent owns one deterministic representative delivery contract at `agents/interior-designer/examples/featured-delivery.json`. Generate delivery version 2 from a quality-gated v2 project with the contract command. Do not recreate a visually similar Page.

The fixed structure uses the historical `su-design-classic` full-canvas shell: a pale edge-to-edge canvas, floating header, three-item bottom-left navigation (`SU 设计稿`, `户型图`, `用户需求`), bottom-center viewing tools, and bottom-right gesture guidance. The governed audit stays embedded in the artifact instead of becoming a fourth visual navigation destination. The Page includes the user-uploaded source-plan image, the Agent-uploaded revision-annotation image, Pascal design model, requirements and revision history, floor selection, real doors/windows and key components, visibly distinct 3D/orthographic views, labels, desktop/mobile-landscape layouts, concept comparison when multiple concepts exist, stacked/solo/exploded levels, issue and requirement highlighting, assumptions, unknowns, professional verification, revision summary, and a model-derived SVG failure fallback. A justified single-concept delivery hides the meaningless concept switch.

The Page must warm the viewer automatically. A dedicated loading surface, not a model-derived plan, covers the Canvas until the first valid frame. Labels and viewing controls stay unavailable during that interval, and scheduled invalidations cover cold-start layout and font timing. Displaying 3D may never depend on a click, drag, mode switch, or other user input. A real viewer error may reveal the accessible model-derived SVG fallback. The 3D control uses an isometric perspective pose; the 平面 control uses a top-down orthographic pose and late stabilization may not reset it to perspective.

The Page is a read-only artifact. It cannot save scene changes, call MCP or Agent tools, read files, access loopback, load remote content, execute evidence markup, or contain Space/owner/managed-object IDs. CSP denies network, frames, plugins, external fonts, workers, media, and form submission. Only the redacted user source-plan image, redacted Agent revision-annotation image, and minimal viewer payload are embedded. The 户型图 panel renders both with ordinary `<img>` elements and performs no SVG, Canvas, or DOM annotation drawing. The source image hash, project provenance, selected concept, compiled scene model basis, and Page payload must agree; this ensures 3D, orthographic plan, labels, and design explanations are derived from the displayed user upload rather than a generic sample model.

Generation writes exactly `index.html`, `scene.json`, `audit.json`, and `manifest.json`; the directory limit is 20 MiB. The manifest records interior-designer Agent identity, Agent version, representative example ID, delivery version, engine and rendering profiles. It must not contain `templateId`, `templateVersion`, `artifactMarker`, or `template.json`. The verifier scans Agent delivery metadata, CSP, remote executable assets, Pascal/CDN hosts, loopback/file URLs, development paths, source maps, and private identity fields.

The Agent representative delivery is not a separately authored preview. `scripts/build-agent-delivery-example.mjs` initializes `examples/professional-agent-example/seed.json` as a governed project, compiles its Pascal scene, runs the same professional audit, calls the same Page generator, derives an isometric `cover.svg` from the selected model, and records seed, evidence, project, scene, audit, and file hashes in the committed manifest. The representative delivery also enforces a non-regression floor of 12 rooms, 30 procedural furniture/equipment items, 14 openings, 8 doors, and 6 windows, plus model labels and requirement highlighting. These thresholds protect the product example quality reference; customer projects must reflect actual evidence rather than inventing elements to satisfy the example floor. `--check` regenerates the artifact and fails on any byte or quality drift.

Publication uses the generic `pa-cli pages publish --file <page.html> --folder <page-folder> --json` contract without `--template`. Record the returned immutable Page ID and governed Page metadata. Natural-language changes return to the main Agent, create a structured revision, rerun the gate, generate a new artifact, and publish a new version. Rollback selects a previous immutable artifact.

Automated acceptance covers code, schema, scene, semantic HTML, accessibility markers, CSP, privacy, routes, size, deterministic hashes, the classic layout marker, and the automatic viewer lifecycle contract. Do not mark visual acceptance passed. Report `visualAcceptance: user` and keep it pending until the user reviews desktop and mobile interaction.
