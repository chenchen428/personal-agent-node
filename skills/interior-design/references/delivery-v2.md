# Interior-design delivery v2

The interior-designer Agent owns one deterministic representative delivery contract at `agents/interior-designer/examples/featured-delivery.json`. Generate delivery version 2 from a quality-gated v2 project with the contract command. Do not recreate a visually similar Page.

The fixed structure uses the historical `su-design-classic` full-canvas shell: a pale edge-to-edge canvas, floating header, four-item bottom-left navigation (`需求`, `设计稿`, `效果图`, `流程`) when a governed render set exists, bottom-center viewing tools, and bottom-right gesture guidance. 需求 combines the redacted source plan, Agent annotation, requirements, professional boundaries, and revision history. 效果图 uses one main viewing area plus an ordered strip; sequence follows the confirmed storyboard from public-room context through supporting views to private space, rather than filename or generation time. 流程 exposes the eight stages, user confirmation trail, and confirmed style contract. Concept renders cannot replace construction drawings or material samples. The governed audit stays embedded instead of becoming another visual destination. Without a governed render set, generation retains the evidence-first fallback navigation.

The Page must warm the viewer automatically. A dedicated loading surface, not a model-derived plan, covers the Canvas until the first valid frame. Labels and viewing controls stay unavailable during that interval, and scheduled invalidations cover cold-start layout and font timing. Displaying 3D may never depend on a click, drag, mode switch, or other user input. A real viewer error may reveal the accessible model-derived SVG fallback. The 3D control uses an isometric perspective pose; the 平面 control uses a top-down orthographic pose and late stabilization may not reset it to perspective.

The Page is a read-only artifact. It cannot save scene changes, call MCP or Agent tools, read files, access loopback, load remote content, execute evidence markup, or contain Space/owner/managed-object IDs. CSP denies network, frames, plugins, external fonts, workers, media, and form submission. The redacted user source-plan image and redacted Agent revision-annotation image remain separate same-origin files referenced by ordinary `<img>` elements; only the minimal sanitized viewer payload is embedded in the HTML. The 户型图 panel performs no SVG, Canvas, or DOM annotation drawing. The source image hash, project provenance, selected concept, compiled scene model basis, and Page payload must agree; this ensures 3D, orthographic plan, labels, and design explanations are derived from the displayed user upload rather than a generic sample model.

General generation writes `index.html`, `scene.json`, `audit.json`, `manifest.json`, and a `media/` directory. Images are separate same-origin files referenced by relative URL; they are never base64-inlined. The HTML entry stays below the runtime single-file upload limit, and every asset independently obeys the per-file limit; the bundle has no artificial 20 MiB aggregate cap. The committed representative additionally carries model-derived `cover.svg`, with every file recorded by size and SHA-256. Its manifest records interior-designer Agent identity, Agent version, representative example ID, delivery version, engine and rendering profiles, the completed demand-workflow summary, render-set provenance, and evidence hashes. It must not contain `templateId`, `templateVersion`, `artifactMarker`, or `template.json`.

The Agent representative delivery is not a separately authored preview. `scripts/build-agent-delivery-example.mjs` initializes `examples/professional-agent-example/seed.json`, replays all seven confirmed events from `workflow-events.json`, imports the governed imagegen set described by `render-prompts.json`, compiles its Pascal scene, runs the same professional audit, calls the same Page generator, derives an isometric `cover.svg`, and records exact hashes in the committed manifest. Source render PNGs remain generation evidence; the public Page references deterministic delivery-sized WebP derivatives from its `media/` directory to keep each published file bounded. The representative delivery also enforces a non-regression floor of 12 rooms, 30 procedural furniture/equipment items, 14 openings, 8 doors, and 6 windows. `--check` regenerates the artifact and fails on byte, workflow, provenance, or quality drift.

Publication uses `pa-cli pages publish --file <page-dir>/index.html --bundle <page-dir> --folder <page-folder> --json` without `--template`. The CLI uploads each non-entry file independently, then publishes HTML with verified relative-path references; it never sends the image directory as one base64 JSON payload. Record the returned immutable Page ID and governed Page metadata. Natural-language changes return to the main Agent, create a structured revision, rerun the gate, generate a new artifact, and publish a new version. Rollback selects a previous immutable artifact.

Automated acceptance covers code, schema, scene, semantic HTML, accessibility markers, CSP, privacy, routes, size, deterministic hashes, the classic layout marker, and the automatic viewer lifecycle contract.
