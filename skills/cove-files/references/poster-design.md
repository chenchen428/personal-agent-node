# 海报与原生图片交付

日程使用系统模板；发布页海报由 Agent 自由设计主视觉，再由系统绑定当前页面并合成二维码。沿用当前对话与文件能力，不创建专业 Agent、模板市场或额外审批流程。

## 发布页主视觉

先确定读者在三秒内应该明白的一件事，再安排标题、主视觉与少量支持信息。事实来自用户材料和当前发布页；不补造人物、收益、背书或产品能力。

- 建议 1200 × 1600 或 1200 × 1800 像素，导出静态 PNG、JPEG 或 WebP；短边至少800像素。保留源文件和可编辑文案。
- 一个明确的视觉主体，足够大的标题，安静的留白。使用真实图片、插画、图形或大胆的字体构图服务内容；不要把正文逐段装进信息卡片。
- 颜色围绕主视觉展开。Cove 默认暖白、深海绿与海玻璃绿，但发布页海报不必强行套日程模板。使用一至两个强调色，保证正文与背景对比。
- 建立明确的字号与间距层级：标题、支撑信息、行动提示。中文短句按语义换行；正文不能靠缩小字号塞满画布。系列保持配色、字体和阅读节奏一致，变化构图而非品牌身份。
- 避免霓虹渐变、无意义发光、密集徽章、多个争抢注意力的大标题、工具名称和架构术语。装饰不能压过事实与主视觉。
- 默认在右下角保留安静的二维码区域：1200像素画布建议预留约260 × 260像素，距边缘约54像素；支持其他边角。不要把人脸、标题、重要数字或图注放在这里。
- 不自己画二维码，不加入假网址或登录凭据。系统从当前 Space 的已验证页面地址生成二维码，保留四模块静区、至少四像素模块和高对比。底图不裁切、不缩放，系统只在选定角落合成小二维码。
- 图片输入不接受SVG。需要精确排字时可先用自己编写的安全矢量/HTML渲染成PNG；不读取不可信SVG的外部资源，不复制微软字体或私有素材。

## 日程海报

从日程能力查询指定范围的完整结果。检查分页，不能只拿第一页。系统完整展示每项标题、参与人、起止日期时间、时区、状态和可用地点。跨午夜要显示结束日期；所有参与人保留。长备注与跟进记录在链接查看。

内容多时增加图片页数，最多十张；超过限制明确提示用户缩短范围。不要静默省略事项、参与人、标题或把文本挤成小字。无事项时允许一张清楚的留白状态海报。

## 版本与交付

发布页海报绑定当前HTML、被引用资产与页面元数据的版本指纹。生成期间页面发生变化时必须重做；旧海报可保留为历史文件，但不能充当当前页面的海报。

没有可用的手机访问地址时，明确说明暂时无法生成带有效二维码的海报；不要编造回环、localhost、临时链接或token链接。链接仍遵循页面原有访问权限，二维码不会让私有内容自动公开。

完成后检查标题、全部必要信息、留白、文字裁切、完整画幅、二维码实际解码与手机尺寸下的清晰度。图像已渲染和代码检查通过不代表用户已确认美观。

由文件能力把PNG登记为当前Space的受管对象，确认`obj_`可用；主Agent通过现有最终回复附件机制发原生图片，并保留可点击的对应对象链接。不用本机路径代替附件，不让子任务自行发送消息。
