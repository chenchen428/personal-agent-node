# 装修前置设计的 Page 驱动工作流

目标是帮助用户把模糊偏好变成经过逐级可视化确认的前置设计稿，不延伸到施工深化。

## 启动与进度 Page

先生成私有、移动优先的稳定进度 Page，再初始化 `interior-designer/workflow.json` 状态。进度 Page 显示当前阶段、已确认阶段、revision、中间产物 Page 和下一确认门。每次 transition 或反馈回退后覆盖发布同一个 Page，并同步 `publishedRevision`；进度 Page 落后时禁止继续。

长材料、户型图、三维稿和图片不塞进手机聊天。短文字决策直接在消息中确认；所有可视化或长内容必须先发布私有 Page，并把确认绑定到用户实际查看的精确 `pageId`。

## 七个阶段

1. `initial-requirements`（文字确认）：确认成员、生活方式、功能优先级、预算、边界和是否明确授权“按推荐走”。本阶段总要确认。
2. `floorplan-adjustment`（Page 确认）：在原户型图上标注拟拆、拟建、门洞、动线、收纳及结构未知项。拆墙等内容只能标成建议和专业复核项。
3. `three-d-design-review`（Page 确认）：展示家具、尺度关系、材质、灯光和关键细节。未确认不得开始效果图。
4. `render-style-sample`（Page 确认）：只生成一张代表效果图。确认风格、材质、光线和真实感后才能批量生图。
5. `full-render-set`（Page 确认）：从入户门开始，按用户进入住宅和穿行空间的顺序补齐不少于 15 张一致视角。
6. `final-delivery`（Page 确认）：以 PDF 式装修项目设计册作为主体 Page，汇总项目摘要、户型分析、完整设计说明、平面方案、效果图、材料与预算范围、一致性检查、过程确认点、排除项、落地顺序与复尺清单；三维等复杂专业内容使用同 revision 的独立 Page，由主体 Page 在浏览器新页面打开。
7. `delivered`：同步最终进度 Page 后进入终态。

阶段缺少事实、Page、精确确认或当前进度 Page 同步时全部失败关闭。

## 事实状态台账

初步需求阶段就建立事实状态台账，并在每次 revision 后同步：

- `confirmed`：用户明确确认、现场实测或当前官方资料支持；
- `image-derived`：从户型图或现场照片观察、识别或推断，不能当作精确尺寸或结构结论；
- `estimated`：用于概念、尺度或预算规划，保留依据和验证动作；
- `site-measure-required`：实施前必须现场复尺或由相应专业人员复核；
- `excluded`：明确排除的空间、工作或需求，交付中仍显示排除原因。

这些标签映射到 project v2 的证据置信度、观察与推断、假设、未知项、专业复核、范围排除和需求状态，不另造一套互相冲突的项目事实。事实是否可靠、设计是否满足需求、专业复核是否通过是三个独立维度。

## “按推荐走”例外

只有用户明确授权后，才可先完成户型标注和三维设计，并在 `three-d-design-page` 中一次确认这两个阶段。该 Page 必须同时展示标注户型和三维设计的完整审阅内容。这是唯一允许的合并门禁：不能省略初步需求确认，不能绕过一张效果图样张，也不能直接批量生成全量效果图。

## 户型标注

户型调整 Page 至少区分：现状、拟拆、拟建、拟移动、保留、待复核。显示门洞、主要家具尺度、动线、收纳和每个调整的原因。未知承重、管线、燃气、防水和物业许可必须明确标注，不能由图片推断。

## 三维设计稿

三维 Page 让用户核对空间关系，而不是只展示漂亮视角。至少覆盖家具位置与尺寸关系、柜体和收纳、关键材质、灯光层次、门窗关系、设备位置及仍未确定的细节。Page 应提供适合手机的分段内容和必要的大图查看入口。

## 效果图与排版

样张阶段只能有一张图。全量阶段至少 15 张，并从入户门开始形成连续空间叙事，例如：入户、玄关、客厅入口、客厅主视角、客餐关系、餐厅、厨房、走廊、公共卫浴、儿童房、次卧、主卧入口、主卧、衣帽区、主卫；项目实际空间不同则调整顺序但保持连续。

多图 Page 先给全屋路径和编号，再按空间分组。每张图记录空间、视角目的和对应需求；同一空间按全景、关系、功能、细节排列。不同图共享已确认的样张风格，不一致图标记为待修订，不与选定图混排。

样张和全量图必须绑定当前编译场景哈希与镜头 ID，并复核来源户型中的外轮廓、门窗、固定结构和其他已锁定不变量。每个房间与固定元素都需要需求链接和受治理材质；缺少链接时不得以“装饰性补充”为由绕过审计。

## 闭环矩阵与交付清单

最终主体 Page 显示“需求 → 决策 → 场景节点 → 材质/预算范围 → 效果图 → 验收状态”的一致性矩阵。某列不适用时明确写明原因；排除项、未决项、待现场复尺和专业 hold point 不得隐藏。复杂专业 Page 不嵌入主体设计册，而是作为同一交付包内的相对链接；主体设计册与所有子 Page 必须属于相同 revision。

进入完成态前，验证当前 revision 的 `derived/manifest.json`，确认项目、编译场景、专业审计、主体设计册、所有关联专业 Page 和其他资产存在且哈希一致。清单失败、子 Page 链接缺失、引用旧 revision、固定元素无需求来源或效果图不对应当前场景时，回到最早受影响阶段修订。

## 反馈与完成边界

新反馈影响已确认事实时回到最早受影响阶段、创建新 revision，并把下游 Page 标为失效。主体设计册包含需求简报、事实状态台账、标注户型、设计说明、平面方案、样张与全量效果图、材料和预算范围、闭环矩阵、manifest 验证、过程确认、假设、未知项、排除项、专业复核边界与复尺清单；交互式三维设计作为独立关联 Page。交付不包含施工图、结构结论、机电深化、采购、报价承诺或现场执行。
