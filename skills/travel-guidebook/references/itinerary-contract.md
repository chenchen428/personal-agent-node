# 可执行行程规划合同

## 先形成规划数据

在写页面之前先形成结构化规划。每个 Day 必须包含：

```text
日期 / 住宿基点 / 可用时段 / 天气与体力假设 / 当日主题
时间段 / POI / 类型 / 停留 / 下一段交通 / 缓冲 / 预订 / 备选
```

国内路线优先用 `amap-travel-routing` 解析 POI 和相邻路段。高德只解决
地点身份、距离和路线估算；开放时间、预约、天气、票价和安全继续使用对应
官方来源。

## 页面必须回答的问题

### 全程概览

- 从哪里出发，哪天到达和离开；
- 同行成员、步行承受、饮食与无障碍限制；
- 每晚住哪里，为什么选这个基点；
- 预算区间、已订项目和最晚决策日期；
- 哪些事实已核验，哪些是估算，哪些待用户确认。

### 每日行程

- 明确开始和结束地点，不只列景点名；
- 每个活动给出到达时间、停留时长和离开时间；
- 每段交通给出模式、距离、provider 时长、门到门预算时长和查询时间；
- 每天只安排 2–3 个优先停点，其余标成可选；
- 午餐、晚餐、休息、行李、排队、换乘和返回住宿均进入时间轴；
- 给出触发条件明确的天气、闭馆或体力备选。

### POI 与地图

- 展示最终选定的 POI 名、地址、区域和类型；
- 同名门店、景区入口和车站必须消歧；
- 页面可提供高德搜索或导航入口，但不能把入口当作查询证据；
- 不把 Web 服务 Key 写入页面，不在公开前端调用私密 Key；
- 地图失败时仍能从文字时间轴完成行程。

### 执行清单

- 把预约事项按“立即 / 出发前 7 天 / 前 24 小时”排序；
- 标出已订、待订、无需预订和当天确认；
- 列出价格波动、库存、天气和交通的复核节点；
- 保留一条降级路线，说明删掉什么后仍能完成当天核心目标。

## 可行性门禁

出现任一情况时，不得把当天标成“已核验可执行”：

- 相邻 POI 没有路线证据且无法可靠步行判断；
- 到达时间晚于停止入场或最后交通时间；
- 交通、游览、用餐与缓冲总和超出可用时段；
- 高强度活动连续堆叠且没有恢复时间；
- 雨天备选与主计划地理位置完全不同，切换成本未计算；
- 关键预订、价格或开放信息没有来源或核对时间。

## 来源与状态

对每条动态事实记录：

```text
claim / source URL / retrievedAt / appliesTo / status
```

`status` 使用：

- `verified`：已用当前来源核对；
- `estimate`：用于预算或节奏的明确估算；
- `pending`：缺少凭据或需要临行复核；
- `historical-example`：仅用于代表产物，不应视为当前旅行建议。
