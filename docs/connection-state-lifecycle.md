# 连接状态与授权轮询

连接展示区分已经确认的连接事实、当前授权尝试和暂时无法读取的状态。一次状态查询超时不表示账号已经失效；服务端明确拒绝授权、撤销或环境缺失时仍显示实际问题。

## 授权尝试

- 微信 claw 二维码的确认、失效、取消是当前尝试的终态。确认后停止轮询与过期计时；父组件刷新或回调变化不能重启已经消费的二维码会话。
- 主动重新连接创建新的尝试；已有账号的 connected 状态不能代替新二维码确认。取消、重新生成、清空配置和卸载页面会使旧请求失效。
- 服务端保存授权前检查当前尝试版本，过时的微信确认或 Notion 授权结果不能恢复已经清空的配置。
- 成功提交与连接列表刷新分离。列表刷新失败保留已经发生的授权成功事实，下一次查询继续同步真实状态。

## 查询与恢复

- 每个轮询只有一个在途请求，并有可取消的截止时间。临时网络或服务端查询异常可以重试；明确的终态失败立即停止。
- 连接列表的显式刷新发起新的请求，不复用配置变更前的 GET；旧响应不覆盖后来的成功、清空或重新连接结果。
- Mail / Sites 的验证任务以服务端状态为准。客户端查询失败或等待超时不能自行宣布后台任务失败或取消后台任务。
- 个人微信的测试、配置与清空会更新请求代次；旧 waiting 响应不能把已完成测试退回等待。
- Notion 临时 doctor 失败与明确未授权分开处理，登录轮询与注销串行。
- 小红书和 X 的 OpenCLI 超时显示“状态暂时无法确认”；确实缺少浏览器、CLI 或配置时仍显示需要处理。后续有效检测可恢复正常状态。
- 微信明确返回 401 或凭据过期时，连接列表反映失效；普通网络异常不清除已有凭据，也不伪造一次新的连接成功。

## 验证范围

回归使用虚拟时间、延迟响应、可取消请求及模拟渠道，覆盖确认后再次刷新、截止时间到达、旧请求晚到、主动重连、清空与真实授权失效。连接列表测试经过实际 `fetchJson` 去重逻辑，防止仅有请求代次而仍复用旧传输。

真实账号的扫码、第三方授权和界面交互由用户验收；测试不会读取用户账号凭据或向真实联系人发送消息。
