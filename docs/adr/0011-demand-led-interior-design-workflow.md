# ADR 0011：以需求挖掘为核心的装修前置设计工作流

状态：已由 ADR 0012 的 Page 驱动契约实施
日期：2026-08-01

## 目的与边界

装修设计 Agent 的目标是帮助普通用户把模糊偏好变成可审阅、可追溯的前置设计需求，不是直接进入施工深化。交付止于需求摘要、户型调整方向、3D 概念设计、风格样张、全量概念效果图与最终前置设计 Page。

它不生成或承诺施工图、机电深化、结构结论、材料下单清单、精确工程量、合规结论或现场完成效果。承重、燃气、电气、消防、防水、排水、楼梯结构和现场尺寸继续标记为未知或专业复核项。

## 需求挖掘原则

- 先问家庭成员、生活事件、反例、范围、预算和时间，再归纳专业术语；
- 每轮只问会实质改变结果的少量问题，允许“不确定”和稍后补充；
- 把观察、用户陈述、推断、未知和专业复核分开；
- 风格标签必须拆成可观察的色彩、材质、光、家具轮廓、视觉密度和维护偏好；
- 新反馈影响已确认事实时回到最早受影响阶段，不静默覆盖旧版本。

## Page 驱动阶段

阶段和确认门由 `agents/interior-designer/workflow.json` v2 唯一定义：

1. 初步需求文字确认；
2. 标注户型调整 Page，明确拆除、新建、门洞、功能变化、保留边界和专业风险；
3. 3D 设计稿 Page，证明其模型依据与已确认户型一致；
4. 一张效果图样张 Page，只校准风格、材质、光线和视觉密度；
5. 样张通过后，从入户门开始按空间路径生成不少于十五张全量效果图，并以有逻辑的多图 Page 审阅；
6. 最终前置设计 Page；
7. 同步完成的 `delivered` 终态。

所有 Page 确认绑定准确 `pageId`。每次状态变化后必须覆盖更新同一个移动优先进度 Page；未同步时不得继续。用户明确授权“按推荐走”时，仅户型调整和 3D 可以合并为一个 3D Page 检查点，其余门禁不变。

## 户型与 3D 合同

标注户型必须与用户提供的结构依据同源，区分：

- 明确保留；
- 建议拆除（不推断承重属性）；
- 建议新建；
- 门洞调整；
- 功能迁移；
- 待现场复尺或专业核验。

3D 设计稿必须能追溯到同一 source-plan evidence 和已确认 revision。它用于空间关系、动线、家具尺度意图与材质方向沟通，不冒充 CAD/BIM 或施工模型。

## 样张与全量效果图合同

批量生图前只允许一张代表样张。样张确认至少覆盖主色、木色、表面质感、光色温、家具轮廓、装饰密度和明确避免项。

全量效果图不少于十五张，`view-sequence` 第一项必须是入户视角。排序按以下层级形成叙事：

1. 入户和玄关建立路径；
2. 公共空间连续关系；
3. 餐厨与主要功能动线；
4. 私密空间；
5. 卫浴、家政、收纳等功能空间；
6. 对关键决策有解释价值的材质或构造细节。

每个空间优先按“全景 → 空间关系 → 功能视角 → 细节”排列。多图 Page 使用章节、序号、空间名、视角目的和对应需求，不做无序瀑布流，也不把废弃方向混入最终组。

## 风格参考与生成来源

用户参考图用于提炼风格语言，不等于直接复制。生成图必须基于已确认设计稿、可观察风格合同和对应空间目的重新生成，记录生成器、提示词摘要、参考集合摘要和需求关联。原始私有参考不得复制、裁切拼贴或未经授权发送到外部服务。

内置历史代表案例使用“暖矿物 × 深胡桃木的克制中古”合成方向。它的四张效果图仅用于验证旧代表 Page 的确定性呈现，不是当前十五张门禁的验收证据；新项目一律执行当前 v2 工作流。

## Page 资源与移动体验

Page 是目录资源包，HTML 以同源相对路径引用 `media/` 文件。发布限制按单文件执行，不使用错误的整个 Page 目录 20 MiB 聚合上限，也不为规避限制把图片 base64 内嵌。

进度和审阅 Page 以手机单列为基础：标题、当前决策、关键图、差异说明和确认对象先出现；多图按路径章节分组；桌面再增强为主图加辅助视角或网格。视觉与交互批准始终由用户完成。

## 验收

自动检查至少证明：

- 工作流缺少私有进度 Page 不能初始化；
- 缺少当前 revision 的进度同步不能推进；
- 文字确认和 Page 确认不可混用；
- Page 确认必须引用正确产物 ID；
- 装修样张数量必须恰好为一；
- 全量图必须不少于十五张、路径不少于十五项且从入户开始；
- 推荐模式只能合并户型与 3D 两个阶段；
- 上游反馈会让受影响的下游产物 stale；
- Page 媒体使用相对文件地址，bundle 不受错误的 20 MiB 聚合上限。

视觉质量、空间叙事、移动阅读和浏览器交互由用户最终验收；自动化通过不代表批准。
