# 统一任务计划、日程与执行记录

状态：已实现，用户已授权设计与本机安装；视觉和交互效果待用户验收。

## 用户模型

主菜单为“日程”，提供日程和执行记录两个视图；计划作为共享模型及日程上下文详情保留，不另设计划列表视图。计划保存事项、时间和执行方式；日程是计划发生时间的投影；一次执行产生一个普通任务会话。立即委托的普通任务继续使用既有会话，不要求先建立周期计划。

计划有三种 executionMode：record（仅记录）、remind（提醒本人）、execute（交给 Cove）。默认仅记录；提醒和执行必须有用户意图，不能因为添加参与人而联系他们。executionPrompt 保存完整提醒或执行要求。全部数据仍限定在当前 Space，Agent 修改使用主会话临时能力，浏览器提供只读视图。

## 数据与接口合同

复用 CalendarStore 的受管记录作为计划，保留既有 ID、历史和单次日程，增量加入 recurrence、executionMode、executionPrompt、missedRunPolicy、enabled。新增统一计划列表与运行记录，旧 calendar 和 cron 接口作为兼容入口，不启用两套并行调度。

- recurrence 为 null 或对象：frequency=daily|weekly|monthly|yearly|cron，interval 为正整数，weekdays 使用 JS 周编号0至6（周日为0），until 为带偏移 ISO 截止时间，count 为总发生次数；cron 的 expression 仅兼容既有五字段表达式及其时区。输入字段契约见 schemas/task-plan.schema.json。
- 日历返回每次发生的独立实例；实例携带 planId、occurrenceAt 和独立 id。实例的 occurrenceAt 保持原计划的 UTC 起点，修改开始时间不改变它的身份。
- update 支持 scope=series|occurrence|future，后两者需要 occurrenceAt；默认 series 兼容旧单次接口。本次修改写例外，后续修改拆分系列并保留以前发生的记录；取消通过状态表达。后续拆分不得覆盖已经开始执行的记录，应从尚未开始的下一次修改，避免换系列 ID 后重复执行。
- pa-cli plan list 返回系列，含 nextOccurrenceAt 与最新执行信息；plan show 返回系列；runs 返回按时间倒序的独立执行记录。日程列表按发生时间展开，最近一次不受固定七天窗口限制。
- missedRunPolicy=skip|latest：缺省 skip，停机错过不自动补跑；latest 最多补最近一次，不能积压后集中执行。

## 调度和兼容

统一调度器从计划产生普通任务。record 不运行 Agent。remind 与 execute 使用相同任务记录链路，每次发生以 (planId, occurrenceAt) 去重并在数据库原子领取。已经开始但结果未知的运行不得在重启后静默重做，应显示中断或等待恢复。计划修改和取消后，尚未开始的发生按最新版本处理；历史执行保留原快照。

旧日程作为 record 单次计划保留。旧自动化按稳定来源 ID 幂等导入，保留原始数据、周期、开关与历史关联；监听端口成功后才接管：先完成导入，再关闭旧调度表的开关，由统一计划保留原执行状态，不删除旧数据。回滚旧版本时旧自动化保持暂停，需明确恢复，避免执行已在新版取消或改期的旧规则。兼容 cron CRUD 操作统一存储，避免两个入口分别修改两份时间规则。

## 导航与验收

桌面与移动端使用“日程”主入口，内部只保留“日程 / 执行记录”。两个视图复用固定位置的模块标题、说明和切换栏；摘要和各自筛选区域放在切换栏之后，避免切换布局跳变。旧日程、自动化链接继续可达并落入对应视图。日期范围切换保持最左侧和稳定占位。每个视图有独立页面组件，所有 TSX/JSX 不超过300行。

界面参考 ReUI app-shell-18 的应用壳信息层级，用产品已有兼容组件独立组合实现。只作选型参考，不复制私有素材源码或依赖在线预览。

必须验证：本地时区与夏令时、月末、跨年、截止和次数、三个修改范围、分页和最近一次、并发去重、重启不重复、错过策略、旧数据幂等导入、Space隔离和主会话权限、只读网页、日程与执行互相定位。用户负责视觉与点击体验验收，自动化检查覆盖代码、语义和接口。交付使用不可变本地安装包与原版本回滚目标。
