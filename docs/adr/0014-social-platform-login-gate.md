# ADR 0014：社交平台登录与业务能力检查

日期：2026-09-12。取代 ADR 0008 中只检查执行器、不检查平台登录状态的部分。

## 问题与决定

小红书的浏览器工具已就绪，并不表示用户已在小红书登录或可以搜索。连接目录必须分别表达环境可用、平台登录和业务能力，不能把其中一项当成全部完成。X 等依赖浏览器登录的平台遵守相同规则。

- 环境缺失时引导修复浏览器工具；环境正常但明确未登录时显示未登录/未连接。
- 登录状态未知、页面未准备好、网络异常或验证码/风控阻断时，显示需要确认或处理的具体阶段，不显示已连接。
- 只有可见登录状态已确认且执行环境/只读能力满足合同，才显示连接可用。
- `status` 是只读、脱敏检测。凭据、账号标识、页面正文与浏览器存储不进入连接状态响应。

## 人工登录与恢复

用户需要搜索或读取时，先检查同一浏览器上下文的当前登录状态。未登录则返回平台专用业务阻断与固定官方登录入口，不把它当成 Personal Agent 本机或 Cloud 登录失败。

打开固定站点只要求浏览器环境可用，因此用户能够在尚未登录时打开登录入口。用户在原浏览器中完成登录、扫码、短信、2FA 或验证码处理；产品不代填账号密码、不代过验证。随后重新检测，确认后继续原来已获授权的只读查询。等待超时时保留待处理状态，不假装搜索完成，也不无限重试。

## 执行与隐私边界

登录检查、固定站点打开以及实际 search/read 必须使用同一浏览器 profile，并在对应 Space 与平台的固定操作会话中串行执行，避免检测和搜索落在不同上下文或互相导航。

实现使用固定版本的浏览器执行能力和限域、固定逻辑的适配器。主 Agent 的公开命令面仍只有 `status/open/search/read`；不得开放任意 JavaScript、Cookie、存储或通用浏览器控制入口。SDK 桥在独立子进程中使用过滤过的环境，不继承无关 Personal Agent 密钥。

登录依据来自可靠的可见导航/账号控件或明确登录墙，不以帖子正文关键词判定登录。search/read 前重新检查；执行中出现明确的登录失效时，立即返回平台登录引导。环境就绪缓存不能绕过该检查，未知结果不能复用旧成功作为新证据。

登录检查只读取可见信号。查询所需的同源授权处理留在浏览器内部，Cookie/Token 不导出到 Node/Agent、不进入状态或持久化记录；Twitter 的 CSRF 也在浏览器内组装，仅业务结果出界。小红书和 X 仍是 browser 连接，不拥有可被 Personal Agent 清空的浏览器账号凭据，也不开放发布、点赞、关注或私信操作。

## 验证

模拟未登录、已登录、登录墙、验证码、未知状态、超时、失效与恢复，验证打开登录入口始终可达，未登录没有执行搜索，恢复后使用同 profile 完成原查询，取消或旧请求不覆盖新状态。发行目录必须包含并验证受限 SDK 桥；源运行通过不代替打包后的执行验证。真实登录与浏览器交互由用户验收。
