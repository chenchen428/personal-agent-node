# 装修共创交付 V5 设计规格

状态：V5.4 已确认，按本规格实施
范围：装修设计 Agent 的在线图册、空间推演 3D、确认后的 krpano 全景渲染漫游；不新增用户可选“模式”，不承诺施工级 CAD 文件。

## 1. 调研结论

### 1.1 当前问题不是样式，而是数据与图纸合同过薄

当前三张图共用同一份房间、墙体和洞口，只在总图叠加家具、在另外两图筛选少量点位。它们没有各自的回路、安装高度、管线路径、吊顶边界、设备编号、连续尺寸和图例合同，因此视觉上必然近似。

参考文件的有效信息分为：天花灯位、开关控制、插座点位、给排水、门窗确认、柜体平立面，以及业主对柜体内部和风格的逐条批注。其细节来自“每张图解决不同问题”，不是简单增加线条数量。

### 1.2 参考 VR 是全景节点漫游

目标页面使用 krpano 1.21.1，场景数据包含客餐厅、主卧、次卧三个 panorama tile 节点。用户可以原地 360° 环视并通过热点切换节点，但不是在完整几何模型中任意走动。

因此采用两类连续产物：

1. **空间推演 3D**：可自由查看与进入房间，用于确认布局、尺寸关系、收纳和动线。
2. **视觉确认漫游**：方案确认后，由 Blender 后台从确定视角生成硬结构全景及深度、法线、语义、门洞控制通道；Codex Imagegen 只增强材质、灯光、软装表面与生活细节。生成图经过受约束六分面重组、硬边保留和接缝检查后锁定，以 krpano 门槛热点组成可传播的在线看房页面。

这两个产物属于同一工作流的前后阶段，不让用户选择技术模式。

### 1.3 所有过程产物都可修改

3D 草图是空间推演阶段的确认产物，但不是唯一可修改的产物。图纸、3D 草图、相机视角、内部控制底稿、Imagegen 提示词包、Imagegen 实景全景图、热点关系和最终漫游都可以修改。

工作流采用依赖驱动回退：修改发生在哪个阶段，就重新打开该产物及其确认；只使依赖它的下游产物失效，不无条件回到 3D 草图。

- 修改房间、墙体、门窗、固定柜体或主要家具布局：重新确认相关图纸与 3D 草图，并使受影响的全景节点和最终漫游失效。
- 修改某个全景相机的位置或方向：只重新生成并确认该节点及依赖它的热点，其他已确认节点保持锁定。
- 修改某张全景图的材质、软装、灯光或窗外环境：修改该节点的 Imagegen 提示词包并重做实景全景图，再重新组装和走查最终漫游。
- 修改热点文案、跳转关系或小地图定位：不重做图片，只重新组装和走查漫游。
- 修改设计图纸但不改变共享空间事实：只重新确认对应图纸；若改变共享事实，则按依赖关系同步到 3D 和全景。

每次修改必须保留版本、修改原因、上游修订和失效范围，禁止静默覆盖已确认结果。

## 2. 用户交付结构

Page 只呈现业主需要理解和确认的内容：方案摘要、设计图册、空间推演、全景看房、材料选择和待确认事项。不展示工作区、生成器、几何哈希或实现说明。

设计图册不再固定为三张，而是按当前案例生成以下图纸目录：

| 图号 | 图纸 | 必须表达的信息 |
| --- | --- | --- |
| P-01 | 平面布置图 | 墙体、门窗及开启方向、真实家具符号、房间名/面积、主要净距、总尺寸与分段尺寸 |
| C-01 | 天花灯位图 | 吊顶边界、标高、灯具类型、灯位尺寸、风口/检修口和关键造型 |
| E-01 | 开关控制图 | 开关类型与编号、安装位置、灯具编号、点对点控制关系、图例 |
| E-02 | 插座点位图 | 普通/防水/空调/弱电插座、设备归属、安装高度、图例 |
| W-01 | 给排水图 | 冷水、热水、净水、排水路径，器具节点、标高与图例 |
| M-01… | 重点柜体图 | 柜体平面、立面、分格、柜门开启、内部功能和连续尺寸 |

缺少实测依据的尺寸不得伪造精度：未核实尺寸使用“待复尺”状态和不同线型，只有已验证尺寸才进入正式尺寸链。无对应需求的图纸不生成空壳页。

在线图纸采用单画布 Tab 查看模式，不把六张大图纵向堆叠：

- 顶部固定显示六类图纸 Tab，默认打开 P-01；任一时刻只显示当前图纸，其余图纸完整隐藏。
- 鼠标点击、键盘左右方向键和 Home/End 都能切换 Tab，并明确显示当前选中状态。
- 切换图纸时恢复 100% 缩放和画布原点，避免沿用上一张图的缩放与滚动位置造成误读。
- 缩小、放大、复位、滚轮缩放、拖动画布和“下载当前图纸”全部作用于当前 Tab。
- 手机端 Tab 横向滚动、图纸画布独立滚动，不导致整页被超宽图纸撑开。

## 3. 图纸生成合同

统一空间几何继续作为底层坐标，但新增独立语义层：

- `dimensions`：总尺寸、分段尺寸、净距、标高、来源与置信状态。
- `ceiling`：吊顶区域、跌级、标高、灯具、风口和检修口。
- `circuits`：开关、被控灯具、控制关系与回路编号。
- `outlets`：插座类别、设备归属、安装高度和防水要求。
- `plumbingRuns`：冷热净水与排水路径、节点和标高。
- `cabinetModules`：柜体外框、分格、门板、五金、内部用途和尺寸链。
- `symbols`：统一、可测试的建筑与机电 SVG 符号库。

每张图拥有独立渲染器，而不是一个渲染器切换颜色。统一图框、图号、版本、图例、线宽层级和“方案确认用，施工前需复尺深化”边界说明；支持在线缩放、图层显隐和下载 SVG。

## 4. 空间推演 3D

当前以 `BoxGeometry` 为主的方块模型升级为“语义低模”，但仍明确是布局确认产物：

- 建筑壳体：门扇与开启、门套/把手、窗框/玻璃/窗台、踢脚线、吊顶层级、地面分区。
- 家具与设备：按类别加载可复用 glTF/GLB 资产；沙发、床、桌椅、洁具、电器和柜体不再用同一种盒子代替。
- 材质与光照：基础 PBR 材质、正确 UV 尺度、环境光、阴影和主要灯光色温。
- 交互：稳定的鸟瞰、房间直达、第一人称进入/退出、平面小地图、选中物体后显示尺寸与待确认项。
- 性能：资产分级、实例化、按房间加载，移动端维持可用帧率。

空间推演的验收重点是布局、尺度和功能是否看得懂，不用低质量实时渲染冒充最终效果图。

## 5. 确认后的 krpano 全景渲染漫游

Blender 是空间事实权威：墙体、门窗、固定柜体、吊顶、主要家具、相机以及可通行关系全部由 Blender 和 portal 拓扑确定。每个节点必须输出 360°×180° 等距柱状硬结构底稿、深度、法线、语义、合并门洞蒙版、逐 portal 蒙版和门洞映射。控制通道通过尺寸、相机碰撞、逐门洞可见率、投影、左右接缝和曝光检查后由 Agent 自动验收，不作为用户需要确认的最终图片。

Codex Imagegen 是照片级表面增强环节，不拥有空间解释权。每个节点必须依据硬结构底稿、深度/法线/语义控制图集、门洞蒙版和前一张已锁定风格图，一次生成一张完整的 2:1 等距柱状候选图；只允许补全材质、灯光、软装表面、窗外环境和生活细节。不得新增、删除或移动墙体、门窗、固定柜体、吊顶和主要家具，不得关闭可通行 portal，也不得把门洞画成柜体或墙面。

图片采用逐张确认，不做无确认批量生成：

1. 用户先在语义 3D 中确认一个节点的相机位置和朝向。
2. Blender 后台生成控制底稿并由 Agent 自动检查；用户无需把草模底稿当作实景效果确认。
3. Agent 将已确认设计稿、相机、控制底稿及前一张已确认实景图编译为带哈希的 Imagegen 提示词包；修改提示词包只使依赖它的实景图和漫游失效。
4. Codex Imagegen 读取提示词包及其绑定图片，一次只生成一张完整的照片级实景全景候选图。输入图片最多四张：硬结构底稿、深度/法线/语义 2×2 控制图集、门洞蒙版、前序风格图；各原始控制通道仍独立存档并校验哈希。
5. 合成器把候选图按六个 60° yaw 分面加重叠区重组，分面边界必须避开 portal 与语义硬边保护区；控制图上的门框、墙角、柜体边和吊顶边形成硬边保留闸门，生成图若在对应位置失去边缘响应则拒绝。内置工具若返回低于交付尺寸但不低于 1536×768 的合法 2:1 画布，只允许保持同一投影的确定性 Lanczos 放大到 4096×2048，并在原始 0°/360° 边界窄带内多频段缝合；禁止把坏接缝水平旋转到内部。必须保留原图、尺寸、哈希、六分面相位、重叠宽度、硬边指标、缝合宽度和前后指标，且后处理不得新增设计细节。
6. 自动检查 2:1 全景比例、左右接缝、地平线、逐 portal 可见性、门窗/柜体/吊顶硬边、关键家具位置和相邻节点方向。
7. 用户确认实景图质量和视角；若不通过，只修改这一张并重新确认。
8. 通过后锁定实景图、相机、提示词和修订；用户仍可主动重新打开修改，修改后自动使该节点的下游组装与走查状态失效。
9. 以上一张已确认实景图作为风格约束，再进入下一个节点。

节点数量由可理解的步行距离和门洞可见性决定，不设固定四机位。万象新城案例使用入户玄关、客餐厅公共轴、厨房、卧室走廊、主卧五个节点；若任一跨越仍过远、门洞在球面中不可识别或到达首屏面对墙柜，必须继续增加过渡机位。所有节点确认后，才生成 krpano 场景、门槛热点与到达朝向。

热点不得按房间中心或统一俯角生成。portal 热点绑定门槛地面坐标，waypoint 绑定明确的可行走地面锚点；关闭或不可通行的 portal 不生成进入热点。点击后先平滑转向门洞，再切换场景；目标场景默认按门洞法线设置到达视线，往返方向分别计算。若门外正对墙柜，portal 热点必须用 `arrivalLookAt` 声明穿门后沿下一段可行走路径的转向点，避免进入后第一眼面对墙体或柜体。

图像确认不能只看“好不好看”：Imagegen 实景全景图必须与 Blender 结构控制底稿保持同一空间拓扑、门窗数量与位置、固定柜体、相机高度和热点方向。无法通过接缝或几何一致性检查的图片不得进入 krpano。若用户主动修改实景图或提示词，则重新确认该图，不强制回到 3D 草图；只有修改共享空间事实时才回退到图纸或 3D 阶段。

当验收环境暂时没有合法授权的 `krpano.js` 时，可生成 `pages/tour-preview/` Three.js 无水印验收预览，用于检查图像、门槛热点、点击前转向和到达视线。该页面的 manifest 必须声明 `role=acceptance-preview-not-final-runtime` 与 `finalDeliveryEngine=krpano`，不得确认 `krpano-tour`、`tour-walkthrough` 或最终交付；换入合法运行时后仍须重新组装并完成最终走查。

首批基础资产优先使用授权清楚的 CC0 HDRI、材质和模型，并在资产目录记录来源与许可证；生产发布 krpano 时使用有效的正式许可证。

## 6. 实施拆分

1. 建立版本化产物、确认记录、依赖关系、重新打开和下游失效的标准状态机。
2. 扩展装修场景数据合同和校验器，先让示例案例具备真实不同的图纸信息。
3. 建立六类图纸的独立渲染器、符号库、尺寸链和在线图册目录。
4. 把实时 3D 改为资产目录驱动的语义场景，补齐门窗、家具、柜体、材质与进入房间体验。
5. 增加 Blender 360° 硬结构、深度、法线、语义、逐门洞蒙版与控制图集，Codex Imagegen 受约束表面增强、六分面合成、逐图确认与接缝/硬边检查。
6. 增加 portal/waypoint 拓扑、门槛热点、跳转前转向、目标到达朝向与 krpano 生成器，并执行桌面端和移动端走查。
7. 重新从朋友案例的原始输入走完整流程，逐张请用户确认后输出新的案例工作区并完成最终走查验收。

## 7. 验收标准

- 六类图纸在信息和视觉上明显不同，开关控制、插座高度和水路路径可独立读懂。
- 在线图纸使用单画布 Tab 切换；桌面端和手机端任一时刻只呈现一张图，键盘切换、缩放、复位和下载当前图纸均可用。
- 平面图具备门窗开启、家具符号、尺寸链、图例、图框和版本；不再出现大面积无信息矩形。
- 柜体至少输出一个可读的平面/立面与内部功能分格，能承接业主批注意见。
- 3D 中门窗、吊顶、柜体、洁具、电器和主要家具清楚可辨，用户可以实际进入房间查看。
- 每个全景节点都保留结构控制底稿、Imagegen 提示词包、实景全景候选、用户确认和锁定修订；未经确认的实景图不能进入最终漫游。
- 每个节点都保留深度、法线、语义、合并门洞蒙版、逐 portal 蒙版、控制图集和哈希；任一可通行 portal 缺少独立可见蒙版时不得生成实景图。
- 六分面重组边界避开 portal 与语义硬边，硬边保留指标和首尾接缝均通过；后处理不产生新设计内容。
- 任一过程产物都可以显式重新打开修改；系统能准确列出受影响下游，并只使依赖它们的确认失效。
- 修改单张实景图不会无理由使 3D 草图或其他相机/控制图失效；若后续节点以该图作为风格参考，则只使这些实际依赖的提示词包与实景图失效。修改共享空间事实会使所有实际依赖它的产物失效。
- krpano 全景看房达到“高质量静态渲染 + 360° 环视 + 热点切换”的目标，并在普通网页和手机上可分享查看。
- 最终走查覆盖所有节点、双向门槛热点、点击前转向、到达行进方向、左右接缝、首屏加载、全屏、手机触控和返回设计册。
- 未实测信息始终可辨认，不产生虚假施工精度；视觉与交互最终由用户验收。

## 8. 主要风险

- 高质量结果的瓶颈是空间一致性、家具/材质资产和灯光调校，不是查看器本身；必须建设可授权复用的资产目录。
- 图片生成可能破坏等距柱状投影接缝或改变空间结构，因此必须基于确定性结构控制底稿生成，并逐张执行接缝与几何一致性检查。
- 单图确认会增加交付轮次，但可以避免整批返工，并让相机视角和风格真正由用户锁定。
- 实时自由漫游与照片级全景不能混成一个质量承诺：前者重交互，后者重画质，需保证两者使用同一场景修订。
- 原始图纸若没有可靠尺寸，只能先用于需求确认；实测后再更新正式尺寸链。
